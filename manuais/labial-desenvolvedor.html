2. Conceitos técnicos

RMS: raiz da média dos quadrados das amostras, mede energia do sinal: sqrt(sum(x²)/N). É útil para silêncio/volume, não para identificar fonemas.

Fonema: unidade sonora distintiva. Visema: forma visual associada a um ou vários fonemas. Coarticulação: uma forma começa a se transformar antes de o som seguinte começar.

Alinhamento temporal: atribuir intervalos aos sons da fala. Transcrição de palavras não equivale a alinhamento fonético.

3. Formato JSON experimental

{
  "schemaVersion": 1,
  "application": "WMK Lip Lab",
  "audio": "fala.wav",
  "duration": 3.2,
  "marks": [
    {"time": 0.00, "viseme": "repouso"},
    {"time": 0.25, "viseme": "M/B/P"},
    {"time": 0.40, "viseme": "A"},
    {"time": 0.80, "viseme": "repouso"}
  ]
}

Os tempos são ilustrativos, não são resultados de reconhecimento automático. Ao importar, validar schema, tempos finitos e não negativos, lista de visemas permitidos e tamanho máximo do arquivo.

4. Pipeline recomendado

AudioFile / Microphone
  -> Decoder / AudioWorklet
  -> RMS / VAD (detecção de voz)
  -> [offline: alinhamento fonético / Rhubarb / revisão humana]
  -> VisemeTimeline
  -> Interpolator (coarticulação, easing, duração)
  -> RigAdapter (pesos e deformações da malha da boca)
  -> Renderer / Live / Recorder

O RigAdapter deve receber pesos normalizados e não conhecer DOM, áudio ou provedor de IA. Isso evita acoplamento entre análise e renderização.

5. Interfaces TypeScript propostas

type Viseme = 'rest'|'A'|'E'|'I'|'O'|'U'|'MBP'|'FV';
interface VisemeCue {
  startMs: number;
  endMs: number;
  viseme: Viseme;
  confidence?: number;
}
interface MouthRigAdapter {
  apply(weights: Partial<Record<Viseme, number>>): void;
  reset(): void;
}
interface LipSyncProvider {
  analyze(audio: ArrayBuffer, transcript?: string): Promise<VisemeCue[]>;
}

Essas interfaces são propostas, não arquivos existentes. Separar modo offline de modo Live e aplicar limites de latência e descarte de quadros antigos.

7. Captura de vídeo no navegador

Para vídeo do avatar: canvas.captureStream(30). Para áudio: AudioContext.createMediaStreamDestination(). Combine as trilhas em new MediaStream([...videoTracks,...audioTracks]) e grave com MediaRecorder, verificando MediaRecorder.isTypeSupported. O formato WebM costuma ser mais viável diretamente no navegador; MP4 pode exigir conversão posterior com FFmpeg.

Para exportação determinística, use relógio de composição independente de requestAnimationFrame, capture quadros e codifique com áudio; evite depender da velocidade do computador.

Referências: MDN captureStream e MDN MediaRecorder.

8. Testes obrigatórios

  1. Silêncio: boca permanece em repouso.
  2. M/B/P: lábios realmente se fecham, sem interferência do RMS.
  3. Busca e pausa: timeline não perde o sincronismo.
  4. Exportação/importação JSON: round-trip sem alterar os tempos.
  5. Reprodução em 30/60 FPS: mesma pose para o mesmo tempo.
  6. Áudio com diferentes sample rates e canais.
  7. Permissões de microfone e câmera negadas.
  8. WebM exportado com áudio e vídeo e duração coerentes.
  9. Regressão: editor e Live originais continuam funcionando.

9. Segurança e privacidade

Não incluir chaves Groq ou outras APIs no JavaScript enviado ao navegador. Usar backend local ou servidor com variáveis de ambiente e autenticação. Exibir consentimento antes de transmitir áudio a provedores externos. Limitar tamanho/duração dos arquivos e nunca executar conteúdo do JSON como código.
