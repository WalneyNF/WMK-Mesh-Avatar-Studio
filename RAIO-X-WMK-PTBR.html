WMK Mesh Avatar Studio — Raio X e Manual Inicial

Personalização e estudo técnico: Walney Moreira Klein — walneyk@hotmail.com

1. O que o programa faz?

Transforma uma ilustração 2D em um avatar deformável e animado por malhas. O rig define regiões do rosto, olhos, boca, cabelo e corpo. O editor ajusta pontos e regiões, enquanto a pré-visualização mostra os movimentos.

2. Arquitetura observada

Frontend: React 19 + TypeScript + Vite 7. Rastreamento: MediaPipe Tasks Vision. Editor: src/editor. Modo ao vivo: src/live. Iluminação: src/lighting. Backend: src/server. Pacotes: packages/runtime, packages/element, packages/react e gerador de projetos. Testes: Vitest e Playwright.

3. Primeira execução

cd /d C:\ferramentas\mesh-avatar-studio
npm run doctor
npm run dev

Abra o endereço local indicado pelo Vite. Escolha PT-BR no seletor de idiomas. Abra um projeto existente ou o projeto de exemplo; selecione uma parte à esquerda, ajuste os pontos e observe a prévia. Salve o rig ao terminar.

4. Arquivos do avatar

source.png: imagem original. rig.json: parâmetros geométricos e de movimento. layers.json: camadas da ilustração. built/: recursos processados. Preserve os arquivos relacionados ao importar ou mover um projeto.

5. Comandos de desenvolvimento

npm run build
npm test
npm run lint
npm run e2e
npm run doctor

O navegador Chromium do Playwright é opcional para o editor básico, mas necessário para algumas rotinas de criação e testes visuais. Instale com npx playwright install chromium somente se houver espaço disponível.

6. Internacionalização

O arquivo src/editor/i18n.tsx centraliza parte das traduções. O seletor fica em src/editor/App.tsx. O português foi acrescentado como idioma inicial para instalações sem preferência salva. Módulos especializados ainda podem exibir textos em inglês: é uma tradução parcial e progressiva.

7. Diagnóstico e prioridades

Pontos positivos: arquitetura em módulos, TypeScript, ferramentas de validação e testes automatizados. Riscos: textos espalhados por diferentes dicionários, dependência de arquivos de rig e camadas coerentes, custo de renderização de malhas densas e requisitos de webcam/permissões no modo ao vivo.

Próximas etapas: completar traduções de workflow, exportação, iluminação e Live; revisar nomes e identidade WMK; executar testes de interface e regressão; documentar formato rig.json e integração do runtime em jogos e aplicações.
